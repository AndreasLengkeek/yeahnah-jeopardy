# Server withholds each Clue's Answer from Board/Player until Reveal, instead of broadcasting one shared GameState

ADR 0005 accepted that every client's JS bundle already ships every Answer, so there was nothing to hide server-side — Reveal was just a display decision gated by the UI. That assumption dies with Host-authored Board Config: Clue text and Answers are now Host-supplied content loaded into `GameState` at runtime, not a fixture baked into the build, so both the Board and Player clients need their own copy delivered over the wire rather than importing a shared module. Broadcasting one identical `GameState` to every socket — matching the existing pattern — would mean shipping every Answer to Board and Player clients before Reveal, recreating the exact spoiler risk ADR 0005 dismissed as moot, except now the content is the Host's own authored material rather than public fixture data.

Instead, the server withholds each Active Clue's Answer from the Board and Player payloads entirely: it's included only in the payload sent to the Host's socket, and added to the Board/Player payload only once the Host Reveals. This moves Yeah Nah Jeopardy off single-broadcast `io.emit("state", state)` and onto per-role payloads (or an equivalent per-socket redaction step) for at least this field.

Considered keeping single-broadcast semantics and trusting the client UI to withhold display of the Answer until Reveal, matching today's behavior for the bundled fixture. Rejected: that only held before because the "leak" was inert (public example content already in a public build artifact); a Host's own authored Board is real content a curious Player could inspect in network traffic mid-game, so client-side-only gating stops being defensible once the content is real.
